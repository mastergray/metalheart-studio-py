# Metalheart Studio

Metalheart Studio is a local audio-reactive video authoring project built around the Metalheart/Depthcore renderer. It combines a headless JSON-driven rendering pipeline with a native PySide6/Qt desktop authoring shell. The project does not use a browser frontend, embedded webview, or local web server.

The implementation provides an audio-led native authoring workflow alongside JSON resolution, cached audio analysis, and direct rendering through the immutable audio-reactive reference backend.

## Current status

Metalheart Studio is a functional pre-1.0 vertical slice. The CLI can analyze audio, validate and resolve projects, render complete videos, and export synchronized scene clips. The native editor can create full-track or automatically segmented projects, author the supported form/background/ribbon/finish controls and ordered layer effects, copy looks between scenes, render still and selected-range previews with audio, and launch a cancellable final-video export.

The main remaining version 1 work is structured editing for plates, overlays, and custom reactivity bindings; preview/draft/final selection and scene-clip export in the native UI; scene-aware preview caching and incremental final-render reuse; and release verification on the target Python 3.8 machine. Timeline boundary editing and structural scene operations beyond Copy/Paste are future considerations. See [ROADMAP.md](ROADMAP.md) for the maintained sequence.

## Requirements

- Python 3.8 on the target machine;
- `uv` for the reproducible local environment;
- FFmpeg and ffprobe for rendering and inspection;
- FFplay for range-preview audio when available. Visual range playback remains usable without it.

## Quick start

```bash
uv sync
uv run python studio.py ui examples/layer-effects.json
uv run python studio.py analyze /path/to/song.wav -o song.metalheart.json --scene-mode single --quality preview
uv run python studio.py validate examples/minimal.json
uv run python studio.py resolve examples/minimal.json
uv run python studio.py render examples/minimal.json -o renders/minimal.mp4 --workers auto
uv run python studio.py render examples/multi-scene.json --scene-clips renders/scenes
```

The native editor begins with audio rather than JSON. **New from Audio** can keep a track as one uninterrupted Full Track composition or create phrase-aligned Auto Scenes, then opens the same waveform timeline and analyzed feature cache for either mode. Selecting a scene exposes structured Form, Background, Ribbons, and Finish tabs; each visual layer owns an independent ordered effect stack with catalog-driven property controls. **Copy Scene** and **Paste Scene** transfer the complete authored look between scenes while retaining the destination scene's identity, timing, beat counts, and analysis metadata; Paste participates in project Undo and Redo. Every effect row has a visible enable checkbox, and bypassed instances remain in place with dimmed labels and retained settings. Bounded scene and effect numbers combine a full-rail draggable slider with precise direct number entry. Form, camera, palette, and effect selectors include reviewed offline thumbnails without invoking the renderer while browsing. The inspector reserves enough width for the effect action row, while long labels shrink with full tooltips instead of forcing horizontal scrolling. Radial-only faceting, jaggedness, and geometry controls disable for other forms and are omitted from those authored scenes. Image skins, materials, form geometry, camera, independent form/background/ribbon palettes, background ripple, ribbon settings, PSX finishing, and audio-response presets are editable per scene. Still previews and audio-synchronized selected-range previews use the same capped production renderer; ranges default to four seconds, are bounded to eight seconds for the target machine, and appear directly on the audio waveform as a shaded interval with draggable IN and OUT handles. Range playback uses explicit Play, Stop, and audio-only Mute controls without displaying renderer dimensions or scene metadata in the transport row. Source audio plays through a disposable local FFplay child so a stalled system audio backend cannot block the Qt authoring process; if FFplay is unavailable, visual playback remains usable without audio. A successful preview remains visible and playable after an edit, with a single amber **STALE PREVIEW** badge and a **Restore Preview** action that regenerates the same preview type from the current configuration. Project-level Undo and Redo cover structured edits and applied Advanced JSON, while Save establishes the clean history point. Within the editor, canonical JSON remains available through the optional **View → Advanced Project JSON** dock.

The checked-in 128×72 option thumbnails are pinned to both the renderer revision and a complete catalog fingerprint. Camera and effect choices additionally have 16-frame offline motion studies: cameras sample a representative ten-second path, while effects run through deterministic temporal preroll and changing source/audio signals. Native 256×144 panels play their PNG spritesheets without video codecs or runtime rendering. Regenerate all assets deliberately with `uv run python studio.py thumbnails`; `-o DIRECTORY` can produce a review set without replacing packaged assets. Missing, incomplete, or stale assets fall back to normal text-only native selectors.

Still previews are explicit and deliberately capped at 480×270, 12 fps, 0.2 core scale, and no antialiasing so authoring remains practical on older hardware. Analysis, preview, and full export run outside the UI thread and support cancellation. The native task area shows determinate analysis stages and, during export, current scene/chunk, completed and total frames, elapsed time, and an ETA derived from measured rendered frames. Full export continues to use the authored quality settings.

`analyze` detects tempo, downbeats, and energy and writes a neutral config skeleton that can be edited or rendered directly. `--scene-mode single` creates one full-track composition, while the compatible default `--scene-mode phrases` divides the track into contiguous phrase-aligned scenes. It does not infer sentiment or select aesthetics from audio. Automatic scenes default to a hard five-second maximum: musical boundaries are planned first, then every oversized section is divided into balanced parts without discarding the original boundary. A delayed first downbeat is folded into the opening phrase when preserving it would create a tiny first scene. Use `--bars-per-scene` and `--max-scene-sec` to tune the result (`0` disables the cap), and `--template` to choose the explicit default assigned to every generated scene. The native **New from Audio → Auto Scenes** workflow asks for the same maximum before analysis.

Quality profiles now have concrete defaults: `preview` is 320×180 at 12 fps, `draft` matches the reference fixtures at 960×540 and 24 fps, and `final` is 1920×1080 at 30 fps. Explicit size, FPS, and CRF values override the selected profile.

Each scene may define resolution-independent `overlay.items` with text, position, anchor, size, color, and opacity. `overlay.enabled: false` is the master no-text switch and suppresses both custom items and the reference technical HUD. When overlays are enabled, `overlay.reference_hud` opts into that reference HUD. Reactivity presets expand both native renderer `bindings` and owned `modulators`: frame-space `pulse`, `shake`, `flash`, and `chroma`; camera-space `camera_distance`, `camera_elevation`, `camera_roll`, and `camera_kick`; and form-space controls for scale, deformation, ripple, multidirectional extent, and rotation. Built-in presets treat whole-frame flashing as a restrained transient accent: mapped bands primarily reshape forms and drive configured background ripples, ribbon width/wave/twist/speed, and plate motion. `ferro-impact` retains the strongest deliberate flash accent. The `camera-driven`, `spectral-resonance`, and `spectral-radial` presets supply bounded musical mappings. See `examples/reactive-overlay.json` for explicit per-scene mappings.

The public renderer vocabulary is `palette`, `forms`, `form_len_sec`, and `cameras`. Stable palette IDs include native `steel`, `acid`, `ember`, and the green/gold `jungle`, plus the owned Dazzle adaptations `rainbow`, `ice`, `electric`, `neon`, and `grayscale`; the adaptations preserve ramp identity as static Metalheart lighting rather than importing Dazzle or implying indexed palette cycling. Forms include the reference catalog plus two production-owned abstract geometries: `resonance`, a spectrum-sculpted multi-lobed mass, and `radial`, whose 24 spectrum bands pull the surface along directions distributed around the whole form; see `examples/resonance.json` and `examples/radial.json`. Radial may opt into `form_style` faceting, deterministic object-space jaggedness, and continuous geometric steps. The `spectral-radial-jagged` preset maps amplitude to jaggedness and spectral centroid to detail scale; see `examples/jagged-radial.json`. Optional `renderer.surface` settings replace any 3D core's palette color with a config-relative image using seamless object-space triplanar projection. The `material` setting selects `metallic` reflections or `matte` diffuse lighting. PSX-inspired skins may opt into nearest sampling, stable texture-coordinate steps, and stepped lighting without changing existing renders; see `examples/image-skin.json` and `examples/psx-image-skin.json`. The independent `finish.psx` block lowers the actual scene render resolution before nearest-neighbor enlargement, then optionally reduces each output channel to an authored level count with deterministic 2×2, 4×4, or 8×8 Bayer dithering after post effects. The native **Finish** tab exposes these values per scene; selecting `combined` applies the reviewed 50%-scale, 16-level, Bayer 4×4 recipe, while changing a constituent control detaches the scene to custom values. See `examples/psx-finish.json`.

A 3D scene may select its procedural background color family independently through `background.palette`, or replace that background with a config-relative image through `background.source: "image"`. Procedural palettes use visible color-balanced center and edge stops, while `background.intensity` scales that palette wash from black through vivid without changing image-skin colors. Cover, contain, and tile fitting are supported along with scale, rotation, offset, opacity, dots, foreground ghosts, and shadow controls. The typed `background_pulse` destination changes only background brightness and scale. An optional `background.ripple` surface bends the image with spectrum-directed traveling waves and relights it as flat, matte, or metallic material. `background_ripple`, `background_ripple_scale`, and `background_ripple_impact` independently map overall amplitude, spectral detail, and transient rings while leaving fully opaque form pixels stable; see `examples/image-background.json`. Camera motion may be tuned independently from form animation with `camera_speed`, `camera_phase_sec`, and `camera_intensity`; defaults preserve the reference behavior. Legacy `preset`, `looks`, and `look_len_sec` inputs are accepted during resolution but never appear in resolved profiles. Per-scene `finish` controls own bloom, streaks, flash, chroma, slice glitches, vignette, scanlines, and grain without modifying `ref/`.

Ordered `post` chains provide an owned Glitzle-, Glitchstation-, and Dazzle-derived effect library at scene and global scope. On 3D scenes, the same catalog may also be scoped to `background.post`, `renderer.surface.post`, or `renderer.decor.ribbons.post`; transparent form and ribbon mattes preserve spatial effect movement without filtering the other layers or final text overlay. The catalog contains configurable Glitzle building blocks; a Glitchstation-aligned Color family with `contrast`, `saturation`, `posterize`, `channels`, `grayscale`, and `invert`; Glitchstation shift/block pedals for wrapping `rgb_shift`, directional `tear`, seeded `block_jitter`, and `rectangles`; configurable Glitchstation `vhs` and `arcade` screen processors; the complete 19-preset Glitzle Glitch category; curated Chaos, Decay, Destructive, and Violent presets; five of Glitzle's seven Retro/CRT presets; four Dazzle mirror modes; Dazzle XOR and four-direction Ziti transforms; four-direction VidGlitch-compatible Tetrys; and the Glitzle Studio Glitch Maker effects `chromatic`, `pixel_sort`, and `slitscan`. The catalog marks Datamosh Breakup, Stutter Tear, Bitplane Scramble, Channel Smear, Scanline Desync, and Glitch Warpfield as featured Glitch presets for native UI surfacing. Effects support stable order, enable/bypass, output mixing, typed parameters, deterministic seeded noise, and expansion into portable render profiles. Numeric parameters publish slider step and semantic-role metadata where their source controls define it. `scanlines` is the simple alternating-row treatment; `scanline_corrupt` adds audio-scaled displaced signal bands and chromatic fringing. Audio-aware Glitzle effects expose bounded `audio_scale` parameters. Slitscan declares its finite history requirement, and render workers preroll that history so chunk boundaries do not reset the image. Run `uv run python studio.py list effects --json` for UI-ready metadata and see `examples/effects.json` and `examples/layer-effects.json` for authoring syntax. The sibling projects are not runtime dependencies.

Three-dimensional ribbons and plates are independently authorable through `renderer.decor`. Each family has its own enable switch, deterministic count, metallic or matte material, and optional image surface; ribbons additionally select their color family through `renderer.decor.ribbons.palette`. Ribbon images use longitudinal/twisted-width coordinates that bend with the blade; plate images use planar object-local coordinates. The destinations `ribbon_width`, `ribbon_twist`, `ribbon_wave`, `ribbon_speed`, `plate_orbit`, and `plate_displacement` expose decor motion to ordinary audio bindings. Without explicit layer destinations, mapped bass, mid, and high values drive all six controls conservatively; explicit values, including zero, override those fallbacks. Legacy `decor: true|false` remains valid; see `examples/decor.json`.

Renders split into deterministic chunks. `settings.workers` defaults conservatively to `auto`, `chunk_sec` defaults to four seconds, and completed chunks are retained under `.metalheart-work/` for automatic resume. CLI overrides are available through `--workers`, `--chunk-sec`, and `--no-resume`.

`render CONFIG --scene-clips DIRECTORY` skips assembled-timeline output and renders every scene as an independently playable, audio-synchronized clip. Files use stable ordered names such as `001-intro.mp4`; each receives its own resolved profile and render manifest. Scene-local form skins, background images, ribbon skins, and plate skins remain independent in the exported clips. Global animation time retains the scene's original timeline phase, while scene time still begins at zero.

The minimal example renders three seconds at preview quality. `examples/multi-scene.json` demonstrates an explicit hard cut from Mercury to an Ember/Ferro impact template. Both use the existing audio-reactive reference fixture.
